# 项目文件整理与内容维护重构计划

## Summary（目标概述）
把当前项目从“页面直接读取 data 层（且 generated-content.ts 巨大、依赖 CSV 生成）”重构为 **可维护的内容层（Content Layer）**：以后你修改展览内容主要改少量 **TS 内容文件**，并配套 **类型约束、统一查询 API、内容校验脚本、维护文档**，让代码结构清晰、修改更安全。

你已确认的偏好与授权：
- 未来主要通过 **JSON/TS 文件**修改展览内容（本计划采用 **TS**，更易加注释与类型约束）
- 需要“目录/命名整理 + 文档/脚本”一起做
- 允许兼容性重构（保证页面功能不变/少改，但内部结构更清晰）

### 痛点
1. **generated-content.ts 过大且不适合人工维护**；同时“生成物”与“人工编辑内容入口”混在一起。
2. `artifacts` 与 `exhibitions.units.artifacts` 存在 **重复存储**，未来人工维护容易不一致。
3. 搜索、简体替换、图片 fallback、多图标题解析等逻辑 **分散在页面**，维护成本高。
4. 缺少统一的 **内容一致性校验**（ID 唯一、引用存在、图片存在、多图标题规则等）。

---

## Assumptions & Decisions（假设与决策）
1. **内容维护采用 TS**（不是 JSON）：可以写注释、享受 TypeScript 类型约束；无需额外配置 `tsconfig resolveJsonModule`。
2. 采用“规范化结构（normalized）”：
   - `Artifact`（展品）作为唯一真源（只存一份）
   - `Exhibition/Unit` 仅存 `artifactIds` 引用，不复制整个展品对象
   - 页面需要的 `ExhibitionView/UnitView` 在内容层内部组装（不落盘）
3. 迁移以“可回滚、分步可运行”为原则：每一步完成后项目可 `npm run build`。
4. CSV 导入脚本保留为“可选工具”（批量导入/迁移用），但日常编辑以 TS 内容文件为准。

## Proposed Changes（改动方案）

### 1) 新增内容层目录：`src/content/`
目标：所有“未来会改的文字/数据”集中在 `src/content/`，页面只从这里获取。

建议目录结构（最终态）：
```
src/content/
  index.ts
  site/
    about.ts
    preface.ts
    team.ts
    site.ts            # 可选：站点名/页脚等
  exhibitions/
    artifacts.ts       # 展品表（唯一真源，手改）
    exhibitions.ts     # 展厅结构（章/节/单元，仅引用 artifactIds，手改）
    index.ts           # 查询 API + ViewModel 组装
  text/
    toSimplifiedLite.ts
    imageTitle.ts      # getImageTitleForIndex / getImageTitleSummary
```

### 2) 类型与数据模型（新增/调整 `src/types.ts` 或新增 `src/content/types.ts`）
新增（或移动）内容层专用类型：
- `ArtifactId / ExhibitionId / UnitId`
- `Artifact / Unit / Exhibition`
- `UnitView / ExhibitionView`（给页面用）

数据模型关键点：
- `Unit.artifactIds: ArtifactId[]`（避免复制 artifacts）
- `Artifact.imageUrls: string[]`（统一 fallback 在内容层处理）

### 3) 内容层 API（页面只调用函数，不直接摸数据结构）
在 `src/content/exhibitions/index.ts` 提供稳定接口：
- `getExhibitions(): ExhibitionView[]`
- `getExhibition(exId): ExhibitionView | undefined`
- `getUnit(exId, unitId): UnitView | undefined`
- `getArtifact(id): Artifact | undefined`
- `getAllArtifacts(): Artifact[]`
- `searchArtifacts(query): { art: Artifact; imageIndex: number; url: string; displayTitle: string }[]`
  - 内部统一 `toSimplifiedLite` + 多图标题解析
  - 与现有“浏览展品按图片粒度展开”保持一致

这样页面不再需要自己写：
- 图片 fallback（`?? '/import/picture0.png'`）
- 简体轻量替换
- 多图标题解析/图1图2匹配

### 4) 迁移步骤（关键：保证每一步可运行）
#### Step A：把“站点文案”从 `src/data/content.ts` 拆到 `src/content/site/*`
1. 新建 `src/content/site/about.ts`、`preface.ts`、`team.ts`（建议把长文改为 `paragraphs: string[]`，编辑更舒服）
2. 新建 `src/content/site/index.ts` 做聚合导出
3. 页面（About/Preface/Team）改为从 `src/content` 读取（或由 `src/content/index.ts` 统一导出）

#### Step B：把 `src/lib/utils.ts` 中“内容相关工具”拆到 `src/content/text/*`
将以下函数迁移并保持 API 名称（减少页面改动）：
- `toSimplifiedLite`
- `getImageTitleForIndex`
- `getImageTitleSummary`

（可选）保留 `src/lib/utils.ts` 做转发，等全站迁完再删除。

#### Step C：把展览内容从生成物迁移为可编辑 TS
1. 新建 `src/content/exhibitions/artifacts.ts` 与 `exhibitions.ts`
2. 提供一次性迁移方式（二选一）：
   - 方式 1：改造 `scripts/import-exhibition-csv.ts` 输出到新的 `src/content/exhibitions/*.ts`
   - 方式 2：写一个 `scripts/migrate-generated-to-content.ts` 从 `generated-content.ts` 生成新的内容文件（更贴近当前实际数据）
3. 新建 `src/content/exhibitions/index.ts`：把 `artifactIds` resolve 成 `artifacts`，输出 ViewModel

#### Step D：页面统一切换到内容层 API
逐页替换 import（每改一个页面就跑一次 build）：
- `pages/Exhibitions.tsx / ExhibitionDetail.tsx / ArticleDetail.tsx`
- `pages/Collections.tsx / CollectionDetail.tsx`
- 其它引用 `siteInfo` 的页面

#### Step E：清理旧 data 层
在页面全部迁移后：
- 删除或标记废弃 `src/data/generated-content.ts`
- 将 `src/data/content.ts` 改成仅转发到 `src/content`，或直接删除（取决于是否还有外部引用）
- 更新 `scripts/import-exhibition-csv.ts` 的定位：从“主流程”降级为“可选批量导入工具”

### 5) 新增“内容校验脚本”（长期维护的关键）
新增 `scripts/validate-content.ts`，并在 `package.json` 增加：
- `npm run validate:content`

校验项（失败即退出非 0）：
1. ID 唯一：artifact/exhibition/unit
2. 引用完整：unit.artifactIds 必须存在
3. 图片存在：`/import/*.png` 必须存在于 `public/import/`
4. 字段必填：title/description/source（规则可配置：为空则 warning 或 fail）
5. 多图条目标题可解析：若 `imageUrls.length>1`，但解析不到每图标题则 warning

### 6) 增加维护文档（让你以后改内容“照着做”）
新增文档：`zhanlan-site/docs/content-maintenance.md`，包含：
- 内容入口在哪些文件
- 新增/替换图片的步骤与命名规范
- 多图标题“图1/图2”的写法规范
- 修改后必须运行的命令：`npm run validate:content` + `npm run build`

### 7) “文件整理”建议（不改功能但更干净）
（执行阶段会以“不破坏现有功能”为前提）
- 确保 `dist/`、`node_modules/` 不进入版本控制（`.gitignore` 检查/补齐）
- `src/data/` 最终只保留“兼容转发层”或彻底移除
- 给 `scripts/` 统一命名：`import-*` / `validate-*` / `migrate-*`
