# 全站繁简转换不当检查（统一简体）—计划

## Summary（目标概述）
对项目内**所有会呈现在网站上的文字**进行“繁简混用/繁体残留”检查，目标是最终**统一为简体字**。  
按你的要求，本次只做 **检查与输出清单**，**不自动修改任何内容文件**。

最终交付物为一份报告（Markdown + 可选 JSON），列出：
- 命中的文件路径
- 行号
- 原文片段
- 建议简体（繁→简转换后的文本）

  - 参考文件：[generated-content.ts](computer:///sessions/69f80c2715f4fc8c5a70901b/workspace/zhanlan-site/src/data/generated-content.ts)
- `dist/` 与 `node_modules/` 中也可能出现繁体（构建产物、依赖自带语言包），**不属于“需要改正的源文本”**，必须排除避免噪音。

## Assumptions & Decisions（假设与决策）
1. **本次只检查不改动内容**：不对 `src/`、`csv`、任何源码文件做替换；仅生成报告文件。
2. **检查范围**：按你确认，覆盖“全站代码 + 数据”，但**排除** `node_modules/`、`dist/`、二进制媒体文件。
3. **判断标准**：采用 OpenCC 的 **t2s（繁体→简体）**转换进行对比：若转换结果与原文不同，则判定为“疑似繁体/异体/混用”，需人工确认是否要统一。
4. **报告写入位置**：输出到工作区（你可直接打开查看）：
   - `繁简检查报告.md`
   - `繁简检查报告.json`（可选，便于后续自动化）

## Proposed Changes（实施方案 / 需要做的改动）
> 注意：本阶段“只检查不改”仍需要执行脚本生成报告，因此会新增报告文件（以及临时扫描脚本放在临时目录，不写入项目仓库）。

### A. 编写一次性扫描脚本（临时脚本，不入库）
在临时工作目录中创建并运行脚本（例如 `check_zh_variants.py`），实现：
1. **遍历扫描目标**
   - 目录：`zhanlan-site/`（递归）
   - 额外文件：工作区根目录 `展览内容.csv`
2. **过滤与排除**
   - 排除目录：`node_modules/`、`dist/`、`.git/`、`public/import/`
   - 仅扫描文本后缀（白名单）：`.ts .tsx .js .jsx .json .md .html .css .txt .csv .svg .xml .yml .yaml`
3. **逐行检测逻辑**
   - 仅当行内存在汉字（`[\\u3400-\\u9FFF]`）时才检测
   - `converted = OpenCC.t2s(original)`
   - 若 `converted != original`：
     - 记录问题项：文件、行号、原文片段、建议简体片段
     - 片段做长度截断（例如最多 200 字符），避免报告过大
4. **输出**
   - Markdown：按文件聚合、按行号排序
   - JSON：包含 meta（扫描规则）、summary（命中数）、items（明细）

### B. 依赖选择（脚本内部使用）
优先采用 Python 方案，减少对项目依赖的侵入：
- 尝试使用 `opencc` / `opencc-python-reimplemented`（pip 安装）进行 t2s 转换  
  - 若环境缺失，则在执行阶段安装：`pip install opencc-python-reimplemented --break-system-packages`

### C. 报告结构（示例）
Markdown 报告包含：
1. Summary
   - 扫描文件数
   - 命中条目数
   - Top 命中文件（例如 `src/data/generated-content.ts`）
2. 明细表格
   - `文件 | 行号 | 原文片段 | 建议简体`
